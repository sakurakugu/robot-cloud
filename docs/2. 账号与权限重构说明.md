# 账号与权限说明

本文档描述 `robot-cloud` 当前实际使用的账号、权限和相关数据模型，不再保留旧版“SQLite 方案”描述。

## 当前结论

当前账号系统已经是云端正式能力的一部分，核心特点如下：

- Web 和手机端共用统一账号体系
- 数据存储在 PostgreSQL
- 支持注册、登录、退出、游客模式
- 支持登录设备管理
- 支持用户角色与权限控制
- 机器人连接与用户会话分离

## 当前角色模型

系统内角色为：

- `user`
- `admin`
- `super_admin`

当前约束：

- 第一个成功注册的用户会成为 `super_admin`
- 必须始终至少保留一个 `super_admin`

## 当前主要权限边界

### `user`

- 登录
- 查看个人信息
- 使用普通业务能力

### `admin`

- 具备普通用户能力
- 可管理部分后台内容
- 可管理知识库
- 可管理部分系统配置

### `super_admin`

- 拥有最高权限
- 可修改高风险系统配置
- 可调整用户角色
- 可管理注册配置与系统级参数

## 当前数据库相关表

账号体系当前至少涉及：

- `users`
- `user_sessions`
- `roles`
- `knowledge_entries`

数据库迁移位于：

- `repos/robot-cloud/后端/migrations/`

## 当前主要接口

### 认证

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/guest`
- `GET /api/v1/auth/me`
- `POST /api/v1/auth/logout`

### 登录设备

- `GET /api/v1/auth/sessions`
- `DELETE /api/v1/auth/sessions/:id`

### 用户管理

- `GET /api/v1/auth/users`
- `POST /api/v1/auth/users`
- `PUT /api/v1/auth/users/:id`
- `DELETE /api/v1/auth/users/:id`
- `PUT /api/v1/auth/users/:id/role`
- `PUT /api/v1/auth/register-config`

### 知识库

- `GET /api/v1/knowledge`
- `POST /api/v1/knowledge`
- `PUT /api/v1/knowledge/:id`
- `DELETE /api/v1/knowledge/:id`

## 当前前端对应能力

### Web 端

当前已包含：

- 登录 / 注册 / 游客模式
- 当前账号信息
- 登录设备管理
- 用户管理
- 角色权限限制路由
- 知识库管理

### 手机端

当前已接入：

- 登录 / 注册 / 游客模式
- 当前账号状态展示
- 登录设备页面
- Bearer Token 鉴权请求

## 当前和机器人连接的关系

用户会话与机器人 WebSocket 连接是分开的两条链路：

- 用户登录态进入 `user_sessions`
- 机器人业务连接不写入 `user_sessions`

这意味着：

- 用户设备管理页只管理人的登录设备
- 机器人在线状态不等于用户会话
