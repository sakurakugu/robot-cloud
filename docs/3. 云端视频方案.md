# 云端视频方案

## 目标

当前正式版云端视频链路统一收敛为：

1. 机器狗本地仍产出 `rtsp://127.0.0.1:8554/test`
2. `robot-agent` 使用 `ffmpeg` 将本地 RTSP 持续推送到云端 `MediaMTX`
3. 云端前端调用 `/api/v1/robots/:uuid/video/session`
4. 云端后端只返回云端 WHEP 地址，例如 `/media/robots/<uuid>/whep`
5. 前端通过 WHEP / WebRTC 从云端拉流
6. `coturn` 为浏览器提供 TURN 中继

整个链路只走云端，不再依赖局域网直连，也不再保留本地 WHEP 回退。

## 组件拓扑

云端容器组成如下：

- `nginx`
  - 对外提供统一入口
  - `/` 转发前端
  - `/api/` 转发后端
  - `/media/` 反代到 `MediaMTX` 的 WHEP / WebRTC HTTP 接口
- `backend`
  - 负责机器人列表、视频会话、鉴权与业务控制
  - 在线时返回云端 `whepUrl`
- `mediamtx`
  - 接收机器狗 RTSP 推流
  - 对浏览器提供 WHEP / WebRTC 出流
- `coturn`
  - 提供 TURN 中继，解决公网与复杂网络下的 WebRTC 连通性

## 实际链路

### 机器人上行

机器人端配置 `media.publish_base_url` 后，会把视频推送到：

- `rtsp://<publish_user>:<publish_pass>@<云端主机>:8554/robots/<robot_uuid>`

当前默认实现为常驻 `ffmpeg` 推流，不再等待前端订阅才开始抽帧。

### 浏览器下行

后端对在线机器人返回：

- `mode = cloud`
- `preferredProtocol = whep`
- `whepUrl = /media/robots/<robot_uuid>/whep`

前端拿到这个地址后：

1. 先向 WHEP 地址发送 `OPTIONS`
2. 从响应 `Link` 头中解析 TURN `ice-server`
3. 建立 `RTCPeerConnection`
4. `POST application/sdp` 到 WHEP 地址
5. 将返回的 SDP answer 设置为远端描述

因此浏览器始终连接云端媒体入口，不会再尝试访问机器狗局域网 IP。

## 部署文件

当前仓库已补齐以下部署项：

- `docker-compose.yml`
  - 新增 `mediamtx`
  - 新增 `coturn`
  - `backend` 增加媒体路径配置环境变量
- `nginx/templates/default.conf.template`
  - 新增 `/media/` 反代
  - 修正 WHEP 会话 `Location` 头到 `/media/...`
- `coturn/turnserver.conf`
  - 固定 TURN 监听端口和 relay 端口范围

## 关键环境变量

### 云端侧

- `MEDIA_STREAM_PATH_PREFIX`
  - 默认 `robots`
  - 机器人推流路径前缀，同时也是后端生成 WHEP 地址的路径前缀
- `MEDIA_WHEP_BASE_URL`
  - 默认 `/media`
  - 前端请求 WHEP 时使用的基础路径
- `MEDIA_PUBLIC_HOST`
  - `MediaMTX` 对浏览器宣告的公网域名或公网 IP
- `MEDIA_TURN_DOMAIN`
  - TURN 域名或公网 IP
- `MEDIA_TURN_EXTERNAL_IP`
  - `coturn` 对外宣告的公网 IP
- `MEDIA_TURN_SECRET`
  - `MediaMTX` 与 `coturn` 共享的 TURN 动态凭证密钥
- `MEDIA_PUBLISH_USER`
  - 机器人推流用户名
- `MEDIA_PUBLISH_PASS`
  - 机器人推流密码

### 机器人侧

`sparkrobot-common` 已增加 `[media]` 配置分组，核心字段如下：

- `enable_cloud_streaming`
- `source_rtsp_url`
- `publish_base_url`
  - 默认值建议使用 `follow_server`
  - 表示自动跟随 `server.server_url` 的主机，并固定推流到 `rtsp://<同主机>:8554`
- `stream_path_prefix`
- `publish_user`
- `publish_pass`
- `ffmpeg_path`
- `rtsp_transport`
- `ffmpeg_loglevel`

默认情况下，机器人会把本地 `rtsp://127.0.0.1:8554/test` 推送到与 `server.server_url` 同主机的 `rtsp://<host>:8554/robots/<uuid>`。

## 需要开放的端口

云端安全组 / 防火墙至少需要放行：

- `80/tcp`
- `8554/tcp`
- `8189/tcp`
- `8189/udp`
- `3478/tcp`
- `3478/udp`
- `49160-49200/tcp`
- `49160-49200/udp`

说明：

- `80/tcp` 供前端、后端、WHEP HTTP 入口使用
- `8554/tcp` 供机器人向 `MediaMTX` 推 RTSP
- `8189/tcp/udp` 供 `MediaMTX` WebRTC 直连
- `3478` 与 relay 端口范围供 TURN 使用

## 部署验收与排障

正式版云端视频能否工作，至少要同时满足下面 4 个条件：

1. 机器人业务连接正常
   - 机器人日志里需要出现“业务通道连接成功”“客户端注册成功”
2. 机器人能连到云端 RTSP 发布口
   - 在机器人上执行 `nc -vz <云端主机> 8554`
   - 必须连接成功，不能长期超时
3. 云端 nginx 已经接入 `/media/`
   - 执行 `curl -i -X OPTIONS http://<云端主机>/media/robots/<robot_uuid>/whep`
   - 正常情况下应返回 `204`，并带 `Link` 头
   - 如果返回 `405 Not Allowed`，说明当前部署的 nginx 还没有正确代理到 `MediaMTX`
4. 机器人推流目标与前端拉流目标属于同一套部署
   - `server.server_url` 指向哪一套后端
   - `media.publish_base_url` 就应该指向同一套媒体服务
   - 如果前端连的是本地开发机，而机器人推流到另一台公网主机，前端一定看不到流

推荐先用下面两条命令做最小验收：

```bash
# 在机器人上
nc -vz <云端主机> 8554

# 在任意能访问云端入口的机器上
curl -i -X OPTIONS http://<云端主机>/media/robots/<robot_uuid>/whep
```

常见故障现象与含义：

- 机器人日志里 `ffmpeg` 常驻，但 `ss -tnp` 显示到 `<云端主机>:8554` 为 `SYN-SENT`
  - 表示公网 `8554/tcp` 没打通，通常是安全组、iptables、Docker 端口映射或服务未启动
- `/media/.../whep` 返回 `405`
  - 表示当前云端入口并没有把 `/media/` 转发到 `MediaMTX`
- WHEP 正常但前端仍无画面
  - 优先检查 `MediaMTX` 中是否真的出现 `robots/<robot_uuid>` 发布者
- 机器人能连业务 WebSocket，但前端仍连不上视频
  - 说明业务链路和媒体链路至少有一条没有指向同一套环境

## 当前实现取舍

- 浏览器正式播放链路已经切到 `MediaMTX + coturn + WHEP`
- 云端前端与后端都不再依赖局域网 WHEP 地址
- 机器狗端也不再走业务 WebSocket JPEG 帧流主链路
- 当前 `ffmpeg` 推流默认使用 `-c:v copy`

如果后续发现浏览器兼容性受源 H.264 profile 影响，可再把 `ffmpeg` 改为 `libx264` 转码模式，但这会提高机器狗侧算力占用。

## 推荐配置示例

### 云端 `.env`

```env
SERVER_NAME=robot.example.com
MEDIA_PUBLIC_HOST=robot.example.com
MEDIA_TURN_DOMAIN=robot.example.com
MEDIA_TURN_EXTERNAL_IP=1.2.3.4
MEDIA_TURN_SECRET=replace-with-a-long-random-secret
MEDIA_PUBLISH_USER=robotdog
MEDIA_PUBLISH_PASS=robotdog
MEDIA_STREAM_PATH_PREFIX=robots
MEDIA_WHEP_BASE_URL=/media
```

### 机器人 `config.toml`

```toml
[media]
enable_cloud_streaming = true
source_rtsp_url = "rtsp://127.0.0.1:8554/test"
publish_base_url = "follow_server"
stream_path_prefix = "robots"
publish_user = "robotdog"
publish_pass = "robotdog"
ffmpeg_path = "ffmpeg"
rtsp_transport = "tcp"
ffmpeg_loglevel = "warning"
```

## 结论

当前仓库里的云端视频正式版方案已经统一为：

- 机器狗推云端 `MediaMTX`
- 浏览器拉云端 `WHEP`
- `coturn` 提供公网穿透

不再保留“前端直连机器狗局域网 WHEP”或“业务 WebSocket 转发 JPEG 帧流”作为正式观看方案。
